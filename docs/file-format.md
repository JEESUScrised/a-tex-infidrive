# Формат YTDrive v1

Формат самодостаточный: чтобы восстановить файл, достаточно видео. Внешний JSON не нужен. Все целые числа записаны в порядке big-endian. CRC32 — полином IEEE, тот же, что в `hash/crc32` пакета Go.

## Кадр

Логический кадр по умолчанию — 1280×720, блок 16×16. Сетка 80×45.

Строка 0 не несёт данных:

- блоки 0–3 — чёрная калибровка (яркость 16);
- блоки 4–7 — белая калибровка (яркость 235);
- дальше полосы по 4 блока, чередование белый/чёрный, чтобы кадр было видно глазами.

Бит 0 рисуется яркостью 16, бит 1 — яркостью 235, во всём блоке одинаковый RGB. При чтении берётся средняя яркость внутренних 50% блока по формуле `0.299R + 0.587G + 0.114B`. Порог — середина между измеренными чёрным и белым. Если контраст меньше 24 уровней, кадр пропускается.

Заголовок занимает 40 байт (320 бит), сразу под калибровкой. При 80 столбцах это ровно 4 строки. Дальше идёт полезная нагрузка, до 400 байт.

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | сигнатура `0x59543101` (`YT1` + байт 1) |
| 4 | 1 | версия, сейчас 1 |
| 5 | 1 | режим пикселей: 0 = яркость 1 бит, 1 зарезервирован под DCT |
| 6 | 2 | флаги |
| 8 | 4 | идентификатор файла |
| 12 | 4 | номер кадра с нуля |
| 16 | 4 | число уникальных кадров |
| 20 | 2 | длина полезной нагрузки |
| 22 | 2 | размер блока данных |
| 24 | 2 | сторона блока в пикселях |
| 26 | 2 | столбцов сетки |
| 28 | 2 | строк сетки |
| 30 | 2 | размер XOR-группы, 0 если чётности нет |
| 32 | 2 | число копий пакета |
| 34 | 2 | резерв, нули |
| 36 | 4 | CRC32 байт 0–35 |

Флаги, биты с нуля:

- 0 — исходные данные перед укладкой сжаты gzip;
- 1–3 — режим избыточности: 0 нет, 1 повтор, 2 XOR, 3 повтор и XOR, 4 зарезервирован под Reed-Solomon, 5 зарезервирован под fountain codes.

Если видео уменьшили пропорционально, декодер проецирует ту же сетку 80×45 на фактические пиксели. Поэтому 640×360 после честного масштаба остаётся той же логической сеткой.

## Пакет

Пакеты лежат в полезной нагрузке кадра подряд. Хвост, если он короче пакета, заполнен нулями.

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | сигнатура `0x59545031` (`YTP1`) |
| 4 | 1 | версия 1 |
| 5 | 1 | тип: 1 метаданные, 2 данные, 3 XOR |
| 6 | 2 | те же флаги, что у кадра |
| 8 | 4 | идентификатор файла |
| 12 | 4 | индекс |
| 16 | 4 | сколько таких пакетов всего |
| 20 | 2 | длина полезной нагрузки |
| 22 | 2 | номер копии, с нуля |
| 24 | 4 | номер XOR-группы |
| 28 | 4 | резерв, нули |
| 32 | N | полезная нагрузка |
| 32+N | 4 | CRC32 префикса и нагрузки |

Пакет с неверной суммой отбрасывается. Повтор с тем же индексом не перезаписывает уже принятую копию.

По умолчанию в пакете данных 360 байт. Вместе с префиксом и CRC это 396 байт, то есть один пакет на кадр 720p. Последний пакет короче.

## Метаданные

Метаданные собираются из пакетов типа 1 и описывают исходный файл. SHA-256 считается до gzip.

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | сигнатура `0x59544D31` (`YTM1`) |
| 4 | 1 | версия 1 |
| 5 | 1 | резерв |
| 6 | 2 | флаги |
| 8 | 2 | размер блока данных |
| 10 | 2 | длина имени |
| 12 | 2 | длина MIME |
| 14 | 2 | резерв |
| 16 | 8 | исходный размер |
| 24 | 8 | размер после необязательного gzip |
| 32 | 32 | SHA-256 исходного файла |
| 64 | … | имя, затем MIME |

## Восстановление XOR

Пакеты данных делятся на группы по `parity-group` штук. Последняя группа может быть короче. Пакет чётности — побайтовый XOR нагрузок группы, дополненных нулями до размера блока. Если потерян ровно один пакет и чётность цела, он вычисляется обратно. Две потери в одной группе без дополнительной копии не восстанавливаются, и файл не отдаётся как успешный.
